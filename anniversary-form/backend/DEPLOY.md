# 周年相談フォーム デプロイ手順(GAS + Netlify、初心者向け)

ゴール: フォームで送信すると `kitabatake@cosmic4.com` にメールが届き、ブラウザに「お問い合わせ番号」が表示される。

## しくみ(Netlify Function で中継)

```
ブラウザ ──→ /.netlify/functions/contact ──→ Google Apps Script(/exec) ──→ Gmail送信
   ↑        (Netlify Function・同一オリジン)            │
   └──────────── お問い合わせ番号(JSON) ←──────────────┘
```

- ブラウザから GAS を**直接**呼ぶと、CORS(ブラウザの安全機能)で失敗することがある。そのため、同じサイトの中にある **Netlify Function** を経由する。Function は GAS へサーバー間で送るので CORS の問題が起きず、お問い合わせ番号もブラウザで読める(`no-cors` は使わない)。
- **GAS の URL は `form.js` にも Function のコードにも書かない。** Netlify の**環境変数 `GAS_WEBAPP_URL`** に入れる。
- 作業は大きく2つ: **(A) GAS をデプロイして `/exec` URL を得る(手順1〜5)** → **(B) Netlify にサイトを公開し、環境変数に URL を入れる(手順6〜7)**。

所要時間の目安: 15〜20分。プログラミングの知識は不要です。**コピー&ペーストと、ボタンをクリックする作業だけ**です。

---

## 0. 先に知っておくこと

- Google Apps Script(GAS)は、Googleが無料で貸してくれる「小さなサーバー」です。フォームの送信内容を受け取り、**あなたのGoogleアカウントのGmailから**メールを送ります。
- 送信元のアドレスは、**この手順を実行するGoogleアカウント**になります(例: `xxx@gmail.com` や会社のGoogleアカウント)。受信側の `kitabatake@cosmic4.com` には、そのアドレスから届きます。問い合わせ者への返信は「Reply-To」で問い合わせ者に届くので、そのまま返信できます。
- **パスワードやAPIキーは、どこにも書きません。** Googleの「権限の承認」だけで動きます。
- 用意するもの: ① Googleアカウント(会社用が望ましい。退職などで使えなくならないアカウントを選ぶ) ② `backend/Code.gs` ③ `backend/appsscript.json`(任意だが推奨)

---

## 1. 新しいApps Scriptプロジェクトを作る

1. ブラウザで https://script.google.com を開く。**メール送信に使いたいGoogleアカウントでログイン**していることを確認する(右上のアイコンで確認)。
2. 左上の **「新しいプロジェクト」** をクリックする。
3. 画面左上の「無題のプロジェクト」をクリックし、名前を **「周年相談フォーム受付」** などに変えて「名前を変更」を押す。

## 2. Code.gs を貼る

1. 画面中央のエディタに `function myFunction() { ... }` と書かれている。**中身を全部選択して(Ctrl+A / Mac は Cmd+A)削除する。**
2. このフォルダの **`backend/Code.gs`** を開き、**中身を全部コピー**する。
3. Apps Script のエディタに **貼り付け**(Ctrl+V)する。
4. **Ctrl+S**(Mac は Cmd+S)で保存する。

### 2-2. タイムゾーンの設定(推奨)

1. 左の歯車 **「プロジェクトの設定」** をクリックする。
2. **「「appsscript.json」マニフェスト ファイルをエディタで表示する」** にチェックを入れる。
3. 左の **「エディタ」(`< >` アイコン)** に戻ると、`appsscript.json` というファイルが増えている。それをクリックする。
4. 中身を全部消して、**`backend/appsscript.json` の中身を貼り付け**、保存する。
   - これでタイムゾーンが日本時間(Asia/Tokyo)になり、ウェブアプリの公開設定も推奨値になります。
5. 左のファイル一覧で **`Code.gs`** をクリックして戻る。

## 3. 権限を承認する(試験送信で確認)

まず、**自分宛てに**テストメールを送って、権限を承認します。`kitabatake@cosmic4.com` には送られません。

1. エディタ上部の関数の選択欄(「関数を選択」)で **`testSelf`** を選ぶ。
2. **「▶ 実行」** をクリックする。
3. 「承認が必要です」というダイアログが出たら **「権限を確認」** をクリックする。
4. アカウントを選ぶ。
5. 「このアプリは Google で確認されていません」と出る。これは自分で作ったスクリプトのための表示なので**正常**です。**左下の「詳細」→「(プロジェクト名)(安全ではないページ)に移動」** をクリックする。
6. 「Gmail でメールを送信」などの許可内容を確認して **「許可」** をクリックする。
7. もう一度 **「▶ 実行」** を押す。
8. 画面下の **「実行ログ」** に `実行が完了しました` と、`{"ok":true,"inquiryId":"ANN-20260930-001"}` のような行が出ればOK。
9. **自分のGmailの受信トレイに「【周年相談】ANN-…｜テスト株式会社」というメールが届いている**ことを確認する(数十秒かかることがある。届かないときは迷惑メールも見る)。
10. **`resetInquiryCounter`** を選んで「▶ 実行」する。テストで使った番号をリセットして、本番の最初の受付が `001` から始まるようにします。

## 4. ウェブアプリとしてデプロイする

1. 画面右上の **「デプロイ」→「新しいデプロイ」** をクリックする。
2. 「種類の選択」の横の **歯車アイコン** をクリックして **「ウェブアプリ」** を選ぶ。
3. 次のとおりに設定する。

   | 項目 | 設定 | 意味 |
   |---|---|---|
   | 説明 | `初回公開` など(自由) | 後で見分けるためのメモ |
   | **次のユーザーとして実行** | **自分(あなたのメールアドレス)** | あなたのGmailから送信される |
   | **アクセスできるユーザー** | **全員** | ログインしていない一般の訪問者でも送信できる |

   > 「Google アカウントを持つ全員」を選ぶと、ログインしていない訪問者が送信できず、フォームが動きません。**必ず「全員」** にしてください。
   > 「全員」を選べない場合は、会社のGoogle管理者が外部への公開を制限しています。管理者に相談するか、個人のGoogleアカウントで作り直してください。
4. **「デプロイ」** をクリックする。
5. (承認画面が出たら、手順3と同じように許可する)
6. 「デプロイを更新しました」の画面に **「ウェブアプリ」の URL** が表示される。**「コピー」** を押して控える。
   - `https://script.google.com/macros/s/` で始まり、**`/exec` で終わる**URLです。
   - `/dev` で終わるURLは自分専用のテスト用です。**使いません。**

## 5. URLが動いているか確認する

1. コピーした `/exec` のURLを、**ブラウザの新しいタブに貼り付けて開く**。
2. 画面に次のように表示されればOKです。
   ```
   {"ok":true,"service":"anniversary-contact"}
   ```
   - ログインを求められる → 手順4の「アクセスできるユーザー」が「全員」になっていません。デプロイを編集して直してください(下の「6. 再デプロイが必要になる条件」)。

## 6. Netlify にサイトを公開する(Functions つき)

`form.js` は最初から `/.netlify/functions/contact`(同じサイトの中継API)を呼ぶ設定になっているので、**`form.js` は書き換えません。**

1. このフォルダ(`anniversary-form/`)を Netlify に公開する。**Functions(`netlify/functions/contact.js`)も一緒に公開されている必要がある**ので、次のどちらかで公開する。
   - **Git 連携(おすすめ)**: GitHub 等にこのフォルダをアップロードし、Netlify の「Add new site → Import an existing project」で選ぶ。リポジトリの一部だけを使う場合は「Base directory」に `anniversary-form` を指定する。`netlify.toml` が自動で読み込まれる。
   - **Netlify CLI**: `npm i -g netlify-cli` → このフォルダで `netlify deploy --prod`。
   - ※ 画面にフォルダをドラッグ&ドロップする公開方法では、Functions が動かないことがある。その場合は上の2つを使う。
2. Node.js は 18 以上で動く(`fetch` を使うため)。Netlify の標準設定で問題ない。
3. `netlify.toml` は、`backend/`・`netlify/`・`DESIGN.md` などの内部ファイルをブラウザから見えなくする(404にする)設定も含んでいる。

## 7. 環境変数 GAS_WEBAPP_URL を設定する

1. Netlify のサイトを開く → **Site configuration → Environment variables**。
2. **「Add a variable」→「Add a single variable」**。
   - **Key**: `GAS_WEBAPP_URL`
   - **Value**: 手順4でコピーした `https://script.google.com/macros/s/…/exec`(**`/exec` で終わるもの。`script.googleusercontent.com…echo…` のURLや `/dev` は不可**)
   - Scopes は **Functions** を含める(すべてのままでよい)。
3. 保存する。
4. **環境変数は、次にデプロイするまで反映されない。** **Deploys → Trigger deploy → Deploy site** で再デプロイする。
5. Function が動いているか確認する。次のコマンドで、**わざと不正な内容**を送る(メールは送られない)。
   ```bash
   curl -X POST https://（あなたのサイト）.netlify.app/.netlify/functions/contact -H "Content-Type: application/json" -d "{}"
   ```
   `{"ok":false,"error":"validation","fields":{...}}` が返れば、Function → GAS の中継は成功している。
   - `{"ok":false,"error":"server"}` → `GAS_WEBAPP_URL` が未設定/不正(再デプロイ忘れの可能性)
   - `{"ok":false,"error":"upstream"}` → GAS が JSON を返していない(アクセス権が「全員」でない、`/dev` のURL、デプロイ忘れ)

## 再デプロイが必要になる条件

| やったこと | 再デプロイ | URL |
|---|---|---|
| **`Code.gs` を書き換えた** | **必要**(保存しただけでは、公開中のURLは古いコードのまま) | 変わらない |
| `appsscript.json` の設定(公開範囲など)を変えた | 必要 | 変わらない |
| 「アクセスできるユーザー」「実行ユーザー」を変えた | 必要 | 変わらない |
| 新しい権限(スコープ)が必要な処理を足した | 必要+再承認 | 変わらない |
| `form.js` / `index.html` / `form.css` / `contact.js` だけ変えた | **GASは不要**(Netlifyの再デプロイだけ) | - |
| 送信先メールアドレスを変えた(`CONFIG.TO`) | 必要(`Code.gs` の書き換えだから) | 変わらない |
| **「新しいデプロイ」を押した** | - | **新しいURLになる → Netlify の環境変数 `GAS_WEBAPP_URL` を差し替えて、Netlify も再デプロイ** |

### 再デプロイの手順(URLを変えずに更新する)
1. 右上 **「デプロイ」→「デプロイを管理」** を開く。
2. 現在のデプロイの右にある **✏(編集)** をクリックする。
3. **「バージョン」を「新バージョン」** にする。
4. **「デプロイ」** をクリックする。
   → 同じURLのまま、新しいコードに切り替わります。「新しいデプロイ」を押すと**別のURL**ができてしまうので、更新のときは**必ず「デプロイを管理」→編集**を使ってください。

## 本番確認手順(公開前に必ず1回)

Netlify に公開して環境変数 `GAS_WEBAPP_URL` を設定・再デプロイしたあと、**本番の公開URLで1件送信**して、次を確認します。

| # | 確認すること | OKの状態 |
|---|---|---|
| 1 | フォームから1件送信する | 入力 → 確認 → 「この内容で送信する」の後、完了画面が出る |
| 2 | `kitabatake@cosmic4.com` にメールが届く | 受信トレイ(または迷惑メール)に届いている。数十秒〜1分かかることがある |
| 3 | 件名にお問い合わせ番号が入る | `【周年相談】ANN-20260930-001｜(会社名)` の形 |
| 4 | 本文に必要な情報が入る | お問い合わせ番号、受付日時(日本時間)、会社名、お名前、電話番号、メールアドレス、作りたいもの、ご相談内容、流入情報 |
| 5 | Reply-To で問い合わせ者に返信できる | メールの「返信」を押すと、宛先が**フォームに入力したメールアドレス**になる(送信元のGoogleアカウントではない) |
| 6 | ブラウザに同じお問い合わせ番号が出る | 完了画面の番号 = メールの件名の番号 |
| 7 | 二重送信されない | 「この内容で送信する」を素早く2回押しても、メールは**1通だけ**。同じ内容を2分以内にもう一度送っても、メールは増えず、同じ番号が返る |
| 7-2 | ブラウザのコンソールにCORSエラーが出ない | F12 → Console に `CORS`、`blocked by CORS policy` の赤いエラーがない。Network タブで `contact` のリクエストが `200`、レスポンスが `{"ok":true,"inquiryId":"…"}` |
| 7-3 | 送信失敗時は確認画面のまま | 環境変数を一時的に消すなどして失敗させると、確認画面のまま赤帯が出て、入力内容が残る(確認後に必ず元へ戻す) |
| 8 | 日付ごとに連番が進む | 続けて別の内容で送ると `002`、`003` になる(翌日は `001` に戻る) |

### テスト後の後片付け
- 確認用に使った番号は、本番のカウントに含まれます。公開前に、Apps Script のエディタで **`resetInquiryCounter`** を実行すると、次の受付が `001` から始まります。
- 確認メールは `kitabatake@cosmic4.com` に届くので、「これはテストです」と一言伝えておくと親切です。

## うまくいかないとき

| 症状 | 原因と対処 |
|---|---|
| フォームで「送信できませんでした」が出る | ① Netlify の `GAS_WEBAPP_URL` が未設定/間違い、または設定後に**Netlifyを再デプロイしていない**(手順7のcurlで `server` が返る) ② GAS の「アクセスできるユーザー」が「全員」でない(手順5のURL確認でログイン画面が出る。curlで `upstream`) ③ `/dev` や `echo` のURLを入れている ④ `Code.gs` を直したのにGASを再デプロイしていない ⑤ Functions が公開されていない(`/.netlify/functions/contact` が404。Git連携かCLIで公開する) |
| Netlify の Functions ログを見たい | Netlify → **Logs → Functions → contact**。`[contact]` で始まる行に原因が出る(個人情報の本文は出力しない) |
| 送信に時間がかかって失敗する | Netlify の Function は約10秒で打ち切られるため、8.5秒で待つのをやめて失敗として返す。GASは久しぶりの呼び出しで数秒かかることがあるので、もう一度送信する。**同じ内容の再送は、GAS側が2分間は同じ番号を返すので、メールは二重にならない** |
| 手順5でログイン画面が出る | デプロイを編集し、「アクセスできるユーザー」を **全員** にして再デプロイ |
| 「入力内容に不備があるようです」が出る | サーバー側の検証に引っかかっている。電話番号は0始まりの10〜11桁、メールに `,` `;` `<>` などが入っていないか確認 |
| 「送信できませんでした」だが、メールは届いている | 通信が途中で切れた場合。**もう一度送信しても、同じ内容なら2分以内は二重にならず、同じ番号が返る**。時間が経ってからだと別の番号でもう1通届く |
| メールが届かない | 迷惑メールフォルダ、`kitabatake@cosmic4.com` 側の受信制限を確認。Apps Script左の **「実行数」** でエラーの有無を確認 |
| 「Service invoked too many times: email」 | 1日のメール送信の上限に達した(無料のGmailで約100通/日、Google Workspaceで約1,500通/日)。翌日に回復する |
| 「承認が必要です」が何度も出る | 手順3をやり直し、「詳細」→「(安全ではないページ)に移動」→「許可」まで進む |
| 最初のアクセスだけ遅い(数秒) | GASは久しぶりの呼び出しで起動に時間がかかる。フォームは20秒まで待つ |

## 運用上の注意
- **GAS の `/exec` URL と、Function の `/.netlify/functions/contact` は、どちらも誰でも呼び出せます**(フォームがログイン不要のため)。悪意のある大量送信を防ぐには、`Code.gs` の `isRateLimited_()` にレート制限やreCAPTCHA検証を追加してください。現状は差し込み口だけで未実装です。
- 個人情報が `kitabatake@cosmic4.com` とデプロイしたアカウントの「送信済み」に残ります。運用ルールに合わせて管理してください。
- 送信元のGoogleアカウントを退会/削除するとフォームが止まります。担当者交代のときは、**プロジェクトの共有(右上の「共有」)**で管理者を追加しておくと安心です。
- 送信先を変えるときは `Code.gs` の `CONFIG.TO` を書き換えて、上記の手順で**再デプロイ**します。
