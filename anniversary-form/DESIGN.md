# 周年相談フォーム 設計書(v6)

## 0. 現在の状態
- **フロントエンド**: 実装済み。`index.html` / `form.css` / `form.js`。フローは **入力 → 確認 → 完了** の3ステップ。
- **バックエンド**: ブラウザ → **Netlify Function**(`netlify/functions/contact.js`、同一オリジンの中継) → **Google Apps Script**(`backend/Code.gs`) → Gmail。ローカル検証用に `backend/dev_server.py`。
  - **未デプロイ**: GASのデプロイ(Googleアカウント)、Netlifyへの公開、環境変数 `GAS_WEBAPP_URL` の設定は、それぞれのアカウントでの作業が必要なため未実施。手順は `backend/DEPLOY.md`。
  - **中継にした理由**: ブラウザから GAS の `/exec` を直接 `fetch` すると、リダイレクトを含めて CORS で失敗することがあるため。`no-cors` は応答(お問い合わせ番号)が読めなくなるので使わない。
  - `dev_server.py` はメールを実際には送信せず、`backend/outbox/` に本文を保存する。
- メールの認証情報(Gmailのパスワード、OAuthトークン、APIキー)は、フロントにも本リポジトリのコードにも一切含まない。
- **ビジュアル**: `jcor-anniversary-form.html` をデザイン参照元にして、配色・フォント・カード・入力欄・ラベル・CTAのトーンを合わせた。項目・仕様・送信ロジックは参照元から取り込んでいない(周年、希望時期、その他の追加入力、no-cors送信、クライアント時刻は不採用)。

## 1. UI/UX設計方針
- **目的は「最後まで送信してもらうこと」**。必須5項目+任意1項目。
- **PC・スマホとも1カラム縦並び**。入力順は上から下へ一方向(会社名→お名前→メール→電話→制作物→相談内容→送信)。視線が左右に動かない。
- PCはカード幅680pxに制限し、入力欄が横に長くなりすぎないようにする。スマホは画面幅に合わせる。
- タイピングは会社名・お名前・メール・電話のみ。制作物は1タップの選択式。自由記述は任意で、初期は2行。
- 「未定」を正式な選択肢にして、決めきれない人の離脱を防ぐ。
- **赤エラーは「入力内容を確認する」を押した時に初めて出す**。入力中・blur時は肯定的なフィードバック(緑)だけを出し、不正な値は通常表示のまま何も言わない。
- 装飾より操作性。アニメはスピナーと色の切替のみ。

### 2.5 入力 → 確認 → 完了の3ステップ
| ステップ | 画面 | 動作 |
|---|---|---|
| 1. 入力 | フォーム。CTAは「**入力内容を確認する**」 | 押すとクライアント側で全項目を検証。**API送信はしない** |
| 2. 確認 | 入力内容のプレビュー。「**修正する**」「**この内容で送信する**」 | 「この内容で送信する」を押した時に**初めて**実API(`fetch`)を呼ぶ |
| 3. 完了 | 受付完了+お問い合わせ番号+サマリー | サーバーが返した番号を表示 |

- **入力 → 確認**: 不正な項目があれば確認画面へ進まず、**この時点で初めて赤エラーを表示**し、最初のエラー項目へフォーカスする。入力中・blur時に赤を出さない仕様は維持。
- **確認画面の表示順**は入力と同じ(会社名、お名前、メールアドレス、電話番号、作りたいもの、その他ご相談内容)。各項目は「ラベル→内容」の縦方向の情報ブロック(表ではない)。相談内容が空なら「（なし）」を薄い色で表示。相談内容の改行はそのまま表示(`white-space: pre-wrap`)。
- **修正する**: 入力画面へ戻る。入力値はDOMに残っているので**すべて保持**され、緑の状態も維持される。フォーム先頭付近(見出し)へスクロールする。送信中は操作不可。
- **この内容で送信する**: 二重送信防止(`aria-disabled`+JSガード)、「送信しています…」+スピナー。送信中は「修正する」も `disabled`。
- **送信失敗**: **確認画面のまま**。確認内容・入力内容を保持し、「送信できませんでした。通信環境をご確認のうえ、もう一度お試しください。」の赤帯を表示。同じボタンで再送信できる。入力画面へは強制的に戻さない。サーバーが `validation` を返した場合のみ「入力内容に不備があるようです。「修正する」から内容をご確認ください。」を表示。
- **確認画面の描画は `textContent` のみ**。入力値をHTMLとして展開しない(XSS対策)。`<img onerror=…>` を入力しても文字列として表示されることを確認済み。
- 確認画面のボタンは `<form>` の外の `type="button"`。入力欄のEnterによる暗黙の送信が構造上起きない。

### 電話番号のバリデーション
- 許可する文字: 数字、ハイフン、半角スペース、括弧 `( )`。全角の数字・ハイフン類・括弧・空白は半角へ変換して判定する。
- 判定: 記号を除去した数字列が **0始まりの10〜11桁** なら有効。
  | 入力 | 結果 |
  |---|---|
  | `03-1234-5678` / `0312345678` / `090-1234-5678` / `09012345678` | 有効 |
  | `(03)1234-5678` / `03 1234 5678` / 全角の `０９０ー１２３４ー５６７８` | 有効 |
  | `1234567890`(0で始まらない) / `0312`(桁不足) / `03-1234-567890`(桁超過) / `abc` | 無効 |
  | 空欄 | 必須エラー |
- 画面上の入力値は blur時/送信時に半角へそろえて保持する。IME変換中の書き換えを避けるため、入力中には変換しない。サーバー側でも同じ正規化と再判定を行う。

| 状態 | 表現 |
|---|---|
| 通常(未入力・未検証・入力途中) | 背景 `#F2F4F8`(mist)、枠は透明、角丸6px、余白13px 14px |
| フォーカス中 | 白背景+navy `#2E4A73` の枠+3pxの薄いnavyのリング(最優先で表示) |
| 有効(valid) | 淡い緑背景 `#EFF5F1` + 緑枠 `#8DAE98` + 緑寄りの文字 `#2F5A3F`(彩度を抑えて全体の青灰トーンに馴染ませる) |

- **有効の判定**
  | 項目 | 緑になる条件 |
  |---|---|

## 6. 制作物チップ
- 選択は「押し込まれた面」で表現する。背景・枠・内側の陰影(inset)の方向を「沈む側」に揃える。外向きshadow・太字・チェック風アイコン(`::before` の四角や✓)は使わない。
- 枠は全状態で2px固定なので、選択前後でサイズ・位置が動かない。色は参照デザインのnavy系に合わせている。

  | 未選択 | `#fff` | `#D3DAE5` | ink | なし |
  | hover | `#F2F4F8` | `#A9B6CB` | ink | なし |

- 「未定」は他の制作物と排他: 未定を選ぶと他をすべて解除し、他を選ぶと未定を解除する。内部値は `undecided`。

## 7. Enterキーの扱い(誤送信防止)
**画面遷移・送信はボタンの操作のみ**。日本語IMEは変換確定にEnterを使うため、入力欄のEnterで進んだり送信されたりすると誤操作になる。確認画面でもEnterキーだけでは送信されない。

| 操作 | 動作 |
|---|---|
| 会社名・お名前・メール・電話番号でEnter | 送信しない |
| IME変換確定のEnter | 送信しない(変換の確定自体は通常どおり) |
| チェックボックス(チップ)でEnter | 送信しない |
| textareaでEnter | 改行 |
| 「入力内容を確認する」にフォーカスしてEnter/Space、またはクリック | 確認画面へ進む |
| 確認画面の「この内容で送信する」にフォーカスしてEnter/Space、またはクリック | 送信 |

- 実装は `form` への `keydown` 1か所。`key === 'Enter'` かつ対象が `<input>` の場合に `preventDefault()`。
- `isComposing` の分岐は設けず一律に止める(Safariは変換確定後に `isComposing=false` のkeydownが来るため、フラグ判定だと漏れる)。Enter以外のキーには触れないので、変換中の文字入力は妨げない。

## 9. 送信とメール(サーバー側)
### 9.1 API仕様
経路は2区間ある。

**(1) ブラウザ → Netlify Function**(同一オリジンなのでCORSは発生しない)
- `POST /.netlify/functions/contact`、`Content-Type: application/json`、本文は上記 `collect()` のJSON。`form.js` の `API.url` はこのパスに固定(GASのURLは書かない)。
- 成功(200): `{ "ok": true, "inquiryId": "ANN-20260930-001" }`
- 失敗(必ずJSON): `{ "ok": false, "error": "...", "fields": { ... } }`

  | error | HTTP | 意味 |
  |---|---|---|
  | `validation` | 400 | 入力が不正(Functionでの形式チェック、またはGASの検証) |
  | `too_large` | 413 | 本文が大きすぎる |
  | `rate_limited` | 429 | 連続送信対策で拒否(将来用) |
  | `busy` | 503 | GASが同時送信でロックを取れなかった |
  | `timeout` | 504 | Functionが8.5秒待ってもGASが応答しない |
  | `upstream` | 502 | GASに届かない/GASがJSONを返さない(アクセス権が「全員」でない等) |
  | `server` | 500/502 | 環境変数 `GAS_WEBAPP_URL` の未設定、GAS内部エラー、想定外の応答 |
  | `method_not_allowed` | 405 | POST以外 |

- `form.js` は `res.ok` と本文の `ok === true` と `inquiryId` の3つで成功を判定する。20秒でタイムアウト。失敗時は確認画面のまま、入力内容を保持して赤帯で再試行を促す。`API.url` が `https://` か `/` で始まらない場合は送信しない。

**(2) Netlify Function → GAS**(サーバー間通信)
- `POST {GAS_WEBAPP_URL}`、**`Content-Type: text/plain;charset=utf-8`**、`redirect: 'follow'`。本文は許可したキー(`company, name, email, phone, items, itemsUndecided, message, source`)だけのJSON文字列。想定外のキーは渡さない。
- GAS側は `JSON.parse(e.postData.contents)` で受け取る。GASはHTTPステータスを設定できないので、応答本文の `ok` と `inquiryId` の形(`ANN-YYYYMMDD-NNN`)をFunctionが確認してからブラウザへ返す。
- GASのURLは環境変数 `GAS_WEBAPP_URL`(`https://script.google.com/` で始まるもののみ受け付ける)。コードには書かない。

Functionは薄い中継で、入力の本当の検証・発番・メール送信はGASが行う。Functionは個人情報を含む本文をログに出さない。

### 9.2 サーバーが必ず行うこと
1. **再バリデーション**(クライアントの検証は信用しない): 必須・長さ・メール形式・電話番号(0始まり10〜11桁)・制作物が許可リストに含まれること。`itemsUndecided` はクライアント値を使わず、`items` から再判定。`undecided` を含む場合は他を捨てる。制御文字を除去。
2. **お問い合わせ番号の発番**(下記)
3. **受付日時の生成**(下記)
4. **`kitabatake@cosmic4.com` 宛てにプレーンテキストメールを送信**(`Reply-To` は投稿者のメール)
5. 成功時にお問い合わせ番号をJSONで返す

### 9.3 お問い合わせ番号
- 形式 `ANN-YYYYMMDD-NNN`(例: `ANN-20260930-001`)。日付ごとに連番を1へリセット。1000件を超えた場合は桁が増える。
- **サーバー側で生成**。クライアントでは生成しない。
- 同時送信でも重複しない方式:
  - GAS: `LockService.getScriptLock()` で排他し、`PropertiesService` に「最後に発番した日付」と「その日の連番」を保存。
  - `dev_server.py`: プロセス内ロック+連番ファイル(`.seq.json`)。複数プロセスで動かす場合はDBの採番かOSのファイルロックに置き換えること。
- 発番・メール送信・連番の確定を **1つのロックの中** で行う。メール送信に失敗した場合は連番を進めない(**欠番が出ない**)。ロックが取れなかった場合(30秒待っても他の処理が終わらない)は `busy` を返す。
- 日付は `Asia/Tokyo` で判定する(JST 0:00 で連番が001に戻る。UTCの日付ではない)。
- 二重送信対策(サーバー側): 同じ内容(会社名・お名前・メール・電話・制作物・相談内容)の再送は、**2分間はメールを再送せず、同じ番号を返す**(`CacheService`)。通信断でクライアントが失敗と判断して再送した場合の二重メールを防ぐ。※ `dev_server.py` にはこの機能はない。

### 9.4 受付日時
- サーバー側で `Asia/Tokyo` の日時を生成し、`2026/09/30 16:32` の形式で表示。ブラウザの時刻は使わない。

### 9.6 セキュリティ
- 認証情報はクライアントに置かない。GASは「デプロイした人の権限」で `MailApp` を実行するため、コードに鍵が要らない。自前サーバーで送る場合は環境変数などサーバー側の秘匿領域で管理する。
- `backend/` 配下は静的配信しない(`dev_server.py` は404を返す)。本番でも `outbox/` を公開ディレクトリに置かないこと。
- 連続送信対策の差し込み口として、GASに `isRateLimited_()`、`dev_server.py` に `is_rate_limited()` を用意(現状は常にfalse)。将来ここにIP/メール単位のレート制限やトークン検証(reCAPTCHA等)を入れる。
- ログに本文(個人情報)を出さない。

### 9.7 GASのデプロイと本番確認
手順は **`backend/DEPLOY.md`**(初心者向け)に集約している。要点:
1. Apps Scriptで新規プロジェクトを作り、`backend/Code.gs`(と任意で `appsscript.json`)を貼る。

`Code.gs` の補助関数(エディタから実行): `testSelf()`(自分宛ての試験送信)、`resetInquiryCounter()`(連番リセット)。

**検証状況(Netlify中継)**: `form.js`・`contact.js`・`Code.gs` の実コードを、ブラウザ上でGASとNetlifyの環境を模擬して一連で動かして確認済み。

## 10. 送信中・送信完了・送信失敗
実APIを呼ぶのは確認画面の「この内容で送信する」だけ。
- **送信中**: ボタンが「送信しています…」+スピナーになり、`aria-busy` を付与。再クリックは無効(`aria-disabled` とJSガード。`disabled` にするとフォーカスが失われるため使わない)。「修正する」は `disabled`。
- **送信失敗**: 確認画面のまま(2.5参照)。赤帯を表示し、再送信できる。
- **送信完了**: 確認画面を完了パネルに切替。
  - ✓マーク+「ご相談を受け付けました」
  - **お問い合わせ番号**(サーバーが返した値。クリックで全選択できる)+「お問い合わせの際にこの番号をお伝えいただくと、確認がスムーズです。」
  - サマリー: 会社名、作りたいもの
  - 見出しにフォーカスして読み上げる。スクリーンリーダーには番号も通知する。

## 11. CSS設計案
- BEM+接頭辞 `ann-`。色・余白・角丸は `:root` の `--ann-*` に集約。LPのトークンに差し替え可能。
- 参照デザインのトークン: `--ann-ink #1B2433` / `--ann-navy #2E4A73` / `--ann-navy-soft #DCE3EE` / `--ann-mist #F2F4F8` / `--ann-line #D3DAE5` / `--ann-muted #5E6878` / `--ann-error #B3261E`。
- フォントは **Zen Kaku Gothic New**(第一候補。Google Fontsを `index.html` の `<link>` で読み込み)。フォールバックは Hiragino Kaku Gothic ProN / Hiragino Sans / Noto Sans JP / Yu Gothic UI / Meiryo。見出しも明朝ではなくゴシックで統一。
- ラベルは16px・700・必須/任意バッジを横並び。必須はnavy背景+白文字、任意はmist背景+mutedの文字+lineの枠。
- 主なクラス: `ann-contact`(外枠)、`ann-contact__head`、`ann-contact__inner`(カード)、`ann-form__fields`(縦並び)、`ann-field`、`ann-input`、`ann-chip*`、`ann-button`(`--ghost`)、`ann-confirm*`、`ann-alert`、`ann-done*`、`ann-site-head*`(デモ用ヘッダー)。
- ブレークポイントは521pxの1つだけ(カード表現と余白)。`prefers-reduced-motion` 対応。
- `.ann-contact` に `overflow-x: clip` を使用(`hidden` にすると縦スクロール容器になる)。

## 12. アクセシビリティ
- `label[for]` と `input` を紐付け。選択項目は `fieldset` / `legend`。
- エラーは `aria-invalid` と `aria-describedby` で結びつける。確認へ進む時は最初のエラー項目へフォーカス。
- 確認・送信中・完了は `role=status`(`aria-live=polite`)で通知(非表示の親の外に配置)。通信失敗の赤帯は `role=alert`。
- 画面切替時は見出しにフォーカスを移す(`tabindex=-1`)。
- `:focus-visible` を全操作要素に用意。選択状態は色だけでなく、押し込み表現(枠・背景・内側の陰影)で示す。
- 入力欄は16px以上(iOSの自動ズーム防止)。最小タップ高さはPC 44px、スマホ 48px。

## 13. 実装時の注意点
- プライバシーポリシーのリンク(`#privacy`)と注記文は仮置き。
- Google Fontsは外部読み込み。オフラインや読み込み失敗時はフォールバックのゴシック体で表示される。LP側で同じフォントを既に読み込んでいる場合は `<link>` を重複させないこと。
- 確認画面のプレビューはブラウザ内の表示のみ。ページを離れる/リロードすると入力内容は消える(保存していない)。
- 電話番号は「0始まり」を必須条件にしている(国内番号のみ)。海外番号を受けたい場合は `isValidPhone()` とサーバーの検証を同時に変更すること。
- 検証ロジック(電話・メール・制作物)は `form.js`・`Code.gs`・`dev_server.py` の3か所にある。変更時は3か所を同期すること。
- `netlify.toml` は公開ルートを `.` にしているため、`backend/`・`netlify/`・`DESIGN.md`・`netlify.toml` を404にするリダイレクトを入れている。ファイルを追加したら、公開したくないものが外から見えないか確認すること。
- スパム対策とアクセス解析は未実装。
- 制作物の「その他」を選んでも追加入力欄は出さない。詳細は相談内容欄で受ける。
